# BulletsNdGuns Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite BulletsNdGuns as a typed, server-authoritative TypeScript monorepo (Phaser 4 client, Express 5 + Socket.io 4 server, shared simulation) that plays exactly like the original.

**Architecture:** A pure `shared` package holds a port of Phaser 3.20's arcade tile physics, the level registry, the game rules and the network protocol. The server runs that simulation at 60 Hz per `Room` and broadcasts snapshots. The client predicts its own player with the same code, interpolates everything else, and uses Phaser only to render, play sound and read the keyboard.

**Tech Stack:** Node 24 (native TypeScript type stripping), TypeScript 7, npm workspaces, Express 5, Socket.io 4.8, Phaser 4.2, Vite 8, Vitest 5, ESLint + typescript-eslint + Prettier, concurrently.

**Spec:** `docs/superpowers/specs/2026-11-01-rewrite-design.md` (read it first; its "Current behaviour to preserve" section is the acceptance reference).

## Global Constraints

- Gameplay, UI, art, sound, levels and timings identical to `archive/original` (except the spec's "Original bugs that are fixed" list).
- All code, identifiers, comments, file names and asset file names in English. Player-facing text stays Spanish, always through `t()` in `packages/client/src/i18n`.
- Latest versions: phaser 4.2.x, socket.io / socket.io-client 4.8.x, express 5.x, vite 8.x, vitest 5.x, typescript 7.x. If typescript-eslint (or another tool) rejects TypeScript 7, pin the newest TypeScript it accepts and record why in the README.
- TypeScript `strict: true`, `erasableSyntaxOnly: true` (no enums, namespaces, parameter properties), `verbatimModuleSyntax: true`, relative imports end in `.ts` (`allowImportingTsExtensions` + `noEmit`). Server and shared run directly with `node` (type stripping); only the client is bundled (Vite). If Node type stripping fails for workspace packages, switch the server runner to `tsx` and note it.
- Phaser 4 APIs only: check `node_modules/phaser/skills/<topic>/SKILL.md`, `node_modules/phaser/types/phaser.d.ts` and https://phaser.io/oss/docs/ before using any Phaser API. Do not rely on Phaser 3 memory. Note: `roundPixels` defaults to false in v4, but `pixelArt: true` turns it back on.
- Gameplay physics never uses Phaser physics. The client game config has no `physics` key.
- Constants live in `packages/shared/src/constants.ts`, nowhere else.
- The server alone decides positions, hits, pickups, ammo, score, portals, level changes and the winner. Client messages are only `ready` and `input`.
- Commit after every task with a conventional message (`feat:`, `chore:`, `test:`...) ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A player disconnecting mid-match, including during the tick that completes a level, must not crash the server or stall the match. Tested in Task 7 (`leave during playing removes player and keeps ticking`).
2. Hostile or broken client messages (non-object input, missing fields, non-boolean keys, negative or non-integer `seq`, input floods, `ready` spam) are ignored without crashing or speeding a player up. Tested in Task 6 (`parseInput`) and Task 7 (`input queue drops beyond limit`).
3. A backgrounded browser tab stops sending inputs. The server must not keep repeating the last held keys forever. After `INPUT_STARVATION_TICKS` with no input, the player gets neutral input. Tested in Task 7.
4. Two players touching the same coin or the portal on the same tick. The first player in join order wins, and the level advances exactly once. Tested in Task 5.
5. Snapshots for the previous level arriving after `levelStarted` must be ignored by the client, not drawn on the new map. Tested in Task 11 (`SnapshotBuffer ignores other levels`).

### Geometry reference (Phaser 3.20 semantics, derived from `Body.preUpdate`/`setSize`)

The player sprite is 27x23 at scale 2.3 with origin 0.5, so its display origin is (13.5, 11.5). For a body with source size `(w, h)` and offset `(ox, oy)`, the box is `left = x + 2.3*(ox - 13.5)`, `top = y + 2.3*(oy - 11.5)`, `width = 2.3*w`, `height = 2.3*h`.

| Shape | src size | offset facing right | offset facing left | box width x height | left relative to x |
|---|---|---|---|---|---|
| normal | 12x15 | (2, 8) | (12, 8) | 27.6 x 34.5 | right: -26.45, left: -3.45 |
| narrow (parkour) | 3x15 | (6, 8) | (18, 8) | 6.9 x 34.5 | right: -17.25, left: +10.35 |

`top = y - 8.05` in every case.

- **Bullet:** 4x4 at scale 1.5, origin 0.5. Box 6x6 centred on (x, y).
- **Pickups:** origin (0, 0), drawn at (px, py - 30). Ammo box `(px+11, py-30, 10, 30)`. Coin box `(px+4, py-26, 25, 23)`.
- **Portal:** origin 0.5 at (cx, cy). Box `(cx-22, cy-30, 44, 60)`.

// protocol/input.ts
export interface InputFrame { seq: number; left: boolean; right: boolean; jump: boolean; shoot: boolean }
export const NEUTRAL_INPUT: Omit<InputFrame, 'seq'>;
// simulation/player.ts
export type PlayerId = string;
export type Facing = 'left' | 'right';
export type AnimationKey = 'idle' | 'run' | 'jump' | 'fall' | 'shoot';
export interface PlayerState {
  id: PlayerId; side: Side; x: number; y: number; vx: number; vy: number;
  facing: Facing; narrow: boolean; onFloor: boolean;
  ammo: number; score: number; ticksSinceShot: number; anim: AnimationKey;
}
export interface BulletState { id: string; ownerId: PlayerId; x: number; y: number; vx: number } // id = `${ownerId}:${seq}`
export interface PlayerStepResult { player: PlayerState; bullet: BulletState | null; jumped: boolean }
export function createPlayer(id: PlayerId, side: Side, level: Level, score?: number): PlayerState
  // at spawns[side], facing = side === 'left' ? 'right' : 'left', ammo STARTING_AMMO, ticksSinceShot NEVER_SHOT_TICKS, anim 'idle', narrow false, onFloor false, v 0
export function bodyBox(p: Pick<PlayerState, 'x' | 'y' | 'facing' | 'narrow'>): Rect // geometry table above
export function nextNarrow(p: PlayerState, zone: ParkourZone | null): boolean
export function animationFor(p: PlayerState, input: InputFrame): AnimationKey
export function stepPlayer(player: PlayerState, input: InputFrame, level: Level): PlayerStepResult // pure: returns a new state
```

Order inside `stepPlayer` (reproduces Phaser's "physics step, then scene update" order. Do not reorder):
1. `ticksSinceShot += 1`.
2. `narrow = nextNarrow(player, level.parkourZone)`. In zone: true. Out of zone and facing right: false. Out of zone and facing left: unchanged (the original only resets width when facing right).
3. `anim = animationFor(...)`. `input.shoot && ammo > 0` gives `shoot`. Otherwise, on floor: `vx === 0` gives `idle`, else `run`. In the air: `vy > 0` gives `fall`, else `jump`.
4. Jump: `input.jump && onFloor` sets `vy = JUMP_VELOCITY`, `jumped = true`.
5. Shoot: `input.shoot && ammo > 0 && ticksSinceShot * TICK_MS > SHOT_COOLDOWN_MS` spawns a bullet at `(x, y + 5)`, `vx = ±BULLET_SPEED` by current facing, `id = \`${id}:${input.seq}\``. Then `ammo -= 1`, `ticksSinceShot = 0`.
6. Horizontal: `left` gives `vx = -RUN_SPEED`, facing left. Else `right` gives `vx = RUN_SPEED`, facing right. Else `vx = 0`.
7. Build the `ArcadeBody` from `bodyBox` (with the facing from **before** step 6 and the narrow value from step 2), then `integrate`, `clampToBounds`, `collideWithTiles`. Convert back: `x += box.dx`, `y += box.dy`. Copy `vx`, `vy`, and `onFloor = blocked.down`.

export interface RoomTransport {                // implemented by the socket gateway (Task 8)
  send<E extends keyof ServerToClientEvents>(playerId: PlayerId, event: E, ...args: Parameters<ServerToClientEvents[E]>): void;
}
export interface TickScheduler { start(onTick: () => void): void; stop(): void }
export type RoomPhase =
  | { kind: 'lobby'; ready: Set<PlayerId> }
  | { kind: 'playing'; world: WorldState }
  | { kind: 'gameOver'; scores: MatchScores['scores'] };
export class Room {
  constructor(id: string, transport: RoomTransport, scheduler: TickScheduler);
  readonly id: string;
  get phaseKind(): RoomPhase['kind'];
  get playerIds(): readonly PlayerId[];            // join order
  join(playerId: PlayerId): 'joined' | 'refused';   // refused unless lobby
  leave(playerId: PlayerId): void;
  markReady(playerId: PlayerId): void;
  queueInput(playerId: PlayerId, frame: InputFrame): void;
  tick(): void;                                    // one simulation tick (scheduler calls it; tests call it directly)
}
export class RoomManager {
  constructor(createRoom: (id: string) => Room);
  defaultRoom(): Room;                             // single room 'default' for now
}
export class TickLoop implements TickScheduler {}  // setTimeout loop with accumulator on performance.now(), runs tick() every TICK_MS, catches up at most 5 ticks
```

Behaviour:
- **Sides:** a joining player gets `'left'` if the current player count is even, else `'right'`. Recorded at join and used when the match starts.
- **Start:** after `markReady` or `leave` in lobby, if `players >= MIN_PLAYERS_TO_START` and every player is ready, then `createWorld`, phase `playing`, `send(levelStarted, { levelIndex: 0, snapshot })` to each player, `scheduler.start(tick)`.
- **Inputs:** each player has a queue (max `INPUT_QUEUE_LIMIT`; drop the oldest beyond that). Frames with `seq <=` the last queued or applied seq are ignored. Each tick takes one frame per player. If the queue is empty, reuse the last frame's keys for up to `INPUT_STARVATION_TICKS` empty ticks in a row. From the 7th empty tick on, use `NEUTRAL_INPUT`. `ackSeq` = seq of the last frame actually taken.
- **Tick:** `stepWorld`. On `levelCompleted`: if `isLastLevel`, go to phase `gameOver`, `send(matchEnded, scores)` to all, `scheduler.stop()`. Else `startLevel(next)` and `send(levelStarted)` to all. Otherwise every `SNAPSHOT_EVERY_TICKS` ticks, send `snapshot` (with each recipient's `ackSeq`).
- **Leave:** remove from the phase (lobby ready set, or the world via `removePlayer`) and from the queues. When the last player leaves in any phase: `scheduler.stop()`, phase back to `lobby`.
- Calls with unknown player ids are no-ops.
